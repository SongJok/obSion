较新的首版方案负责收敛原蓝图：保留单一 Python 控制面、PostgreSQL 事务事实源及 Workspace → Thread → Turn → Run → Step → Event 模型。不增加 Java 后端、第二套语义执行器或独立机器人模型调用链。M0—M6 是产品化里程碑，不替代既有 Phase 编号，也不使 Phase 99 自动晋级。

## 首版边界

面向企业私有化部署，容量目标为 100 名用户、10 个活跃项目、10 个并发任务与 3 个并发沙箱。钉钉与 Web 共用身份、权限、任务、证据和审计。

允许的目标能力为授权知识查询、总结、只读分析，以及明确授权范围内的内部创建、外部新增文档和隔离项目副本修改。意图识别不能授予权限。每步执行和最终发送均须重新授权，群消息不能扩大来源 ACL。

沙箱任务最终交付基础提交、补丁、验证命令与退出码、测试结果、未解决问题及复现方式。首版不自动推送代码、创建 PR、合并或部署。原有独立受控动作接口的兼容性与首版启用策略须另行明确，不能因为接口已存在便把它接入自主工具循环，也不能未经 ADR 删除旧契约。

## 产品级验收指标

以下均为目标，不是当前测量值：

- 至少 100 条中文保留任务、30 条真实租户 UAT；按查询、总结、分析、创建及项目处理分别统计。
- 知识有据答案正确率 ≥90%，引用准确率 ≥95%；无依据明确说明不足。
- 有限规模项目任务独立验收成功率 ≥80%，失败保留原因及产物。
- 固定跨租户、跨项目、群受众、提示注入及沙箱攻击集零越权成功。
- 所有工具调用和外部副作用可追溯到真实主体、Run/Step、策略、能力版本和结果。
- 入站持久确认 p95 ≤1 秒，首个状态响应 p95 ≤3 秒，长任务每 15 秒至少一次进度或存活状态。
- 固定模型与知识规模下普通知识问答 p95 ≤30 秒。
- 数据库与对象存储联动实测 RPO ≤15 分钟、RTO ≤60 分钟。
- 必需检查全部通过；未解决 HIGH/CRITICAL 漏洞阻断发布，例外必须具备责任人、到期日及签署。
- 14 天试运行用于上线判定，月度可用性目标为 99.9%；不能以短时本地测试推算月度 SLO。

## 本地回归入口

使用 `make test-local`（依赖已通过 bootstrap 安装）执行本地 Python 与 JavaScript 回归。Python 驱动 `scripts/test_local.py` 在临时空目录运行，移除继承的 `OBSION_*` 和 `PYTEST_*` 配置，关闭第三方 pytest 插件自动加载，仅显式加载 asyncio 插件，并排除现有四类 live 标记。测试路径与仓库配置使用绝对路径，因此不需要读取仓库 `.env`。

该入口不代替真实 PostgreSQL、迁移、租户或容量测试，也不是操作系统网络沙箱。真实集成仍使用专用、明确启用的验证入口；普通回归中的跳过项必须单独记录。原 `make test` 与 CI 契约保持兼容，使用本地部署配置的工作目录应优先选择 `make test-local`。
