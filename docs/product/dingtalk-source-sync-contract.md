# 钉钉组织文档同步契约

状态：目录、受管读取、入库与来源访问屏障已实现；后台自动循环尚在实施。日期：2026-09-11。

用户要求自动获取已授权钉钉组织文档，并用于企业问答。当前已验证 zziv 的真实应用目录读取；
原生块接口存在内容缺失，因此同步不能以 HTTP 成功或返回若干片段作为完整性证明。

## 最低可用闭环

1. 固定来源组织、操作者、连接版本和本地主体；组织识别不依赖客户端当前界面。
2. 自动分页发现组织知识库和企业文件夹；逐层获取节点，保存继续位置与范围。
3. 按实际类型读取正文、表格及附件；保留原始版本、内容摘要和明确的读取缺口。
4. 来源权限与本地主体绑定经过策略判定后入库；文档可见性不自动扩大为全组织。
5. 自动增量更新、恢复失败任务，并让撤销/删除/授权失效的文档停止进入新问答。
6. 用实际提问核对召回、内容、出处和权限；没有来源、来源不完整或版本不明时明确说明。

## 来源与读取接口

每次读取结果至少包含：来源组织、稳定节点编号、类型、来源版本、内容摘要、解析版本、
完整性状态、未支持元素/失败原因、上游访问身份及读取时间。文档正文属于未受信数据，不能
改写工具权限或执行来源文档中的指令。连接凭据不进入正文、模型上下文或同步状态响应。

来源目录目前使用已接入的 Wiki v2；正文读取需独立接口，不能向旧文档路径传新编号。
原生 blocks 接口缺失属性的块必须记录为内容不完整，不可直接视为空白。
完整 JSONML 已由同组织操作者只读取得，证明数据存在；它与应用块接口使用不同认证渠道，
不能把这次操作者读取记录宣称为后台自动同步。完整读取渠道必须接入 Gateway，并固定相同
组织和操作者。若采用本机 DWS 受管读取，需明确标识开发适配器，凭据仍由宿主管理；不能
把任意 shell、动态模块或模型生成参数开放给 Agent，也不能静默替代被上游拒绝的身份。

ADR0114 已实现上述开发受管读取，经真实 Gateway/Policy 读取全部 10 篇已发现的 adoc。
这不是自动入库：当前仅 3 篇解析无缺口；其余图片、卡片、复杂表格和编号等待处理。
实际后台源配置、队列、来源租约与知识库写入是下一项实施工作。

## 持久状态和恢复

同步源、同步运行和逐文档状态应分别持久化于 PostgreSQL。每个源持有连接/组织/授权主体
绑定；每次运行记录代次、租约、发现队列、分页继续位置和预算；文档记录读取版本、最新
权限检查、正文完整性、入库文档编号及失败原因。任务中断后继续未完成项，不从第一页
重复覆盖进度，不把应用内部后台任务当成持久保证。

只有完整扫描一个来源范围后，才可判定该范围内未出现的旧文档已删除。权限拒绝须立即
隔离对应文档；网络错误、预算用尽和部分目录不能当作全量删除依据。来源撤销及主体
映射撤销须阻止新检索，不能只靠下一次内容变化重建权限。相同正文的 ACL 变化仍是授权
更新；来源版本的历史快照不能被覆盖以伪造新鲜度。

## 权限边界

- 同名组织、相同用户名和客户端组织切换不构成身份绑定。
- 钉钉 userId、unionId 与本地 User.id 属于不同标识，不可直接混写到 ACL。
- 权限列表可能包含组织、部门、用户、动态组和继承；未验证的成员关系不产生授权。
- 本地管理员角色不能自动代表对任意外部组织私人文档的读取授权。
- 新检索须检查来源状态、有效的主体映射及权限新鲜度；旧内容可保留审计，不再作为新答案依据。
- 只读主体与应用读取 scopes 分别核对；有目录权限不等于有正文读取权限。

## 验收清单

发送契约补充（2026-09-12，ADR0121）：新版机器人取得令牌后、提交消息前必须重查发送租约、当前组织、收件人、资料和群受众授权。群成员拥有工作区权限不代表能读取答案资料，发送正文须逐人核验；任一成员无权读取时，只能使用已允许的固定完成状态。旧版跨进程明文准备接口拒绝受管资料正文，改用受控 Outbox。该收窄由 [ADR0121](../adr/0121-final-dingtalk-send-authorization.md) 明确批准。

自动发现新文档；子目录和跨页不遗漏；重复执行不制造重复版本；修改后引用新版本；
删除、撤权和关闭来源后不能召回；任务重启后恢复；其他组织/本地未绑定用户不能读取；
包含引用块、列表、表格与未支持元素的文档不会假装完整；未知答案不杜撰；真实点仔问答
及回执通过。所有失败、跳过和未支持类型独立记录，不以成功数量覆盖缺口。
