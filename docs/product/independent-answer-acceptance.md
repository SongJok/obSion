# P1 独立答案验收

状态：实施中，不能据此推进 P1 或 Phase 99。

本需求补齐 P1.3。正常任务仍由唯一 Harness 执行；评分在任务结束后，通过同一 Python
控制面的受认证评测接口完成。评分只读取最终发布答案、冻结问题、审核原文和评分规则，
不把候选任务的 Claim、Critic、VERIFIED、内部推理或自评分交给评分器。

## 必须实现

1. 候选输入只包含原问题，保留集引文和规则不进入候选 Thread、Memory 或检索索引。
2. 服务端重新检查任务、工作空间、原文访问权限和当前版本，核对原问题、原文摘要与实际
   发布答案摘要。客户端不能以自报答案替换被测结果。
3. 使用显式选择且受冻结配置约束的评测模型，通过既有 Model Gateway 调用；评分有独立
   时间、令牌和费用上限，调用和 Policy 留有审计，不改变候选 Run 的状态、费用或答案。
4. 每项规则产生独立判断和理由，严格检查规则覆盖；可答问题的错误拒答计 FAIL，无资料
   问题的正确弃答单独统计。模型自称通过不够，必须同时完整评价正确性、完成度及全部规则。
5. 原文、问题、答案作为不可信数据，不能要求评分器改变评分规则或调用工具。
6. 模型不可用、输出截断、结构无效、来源变化、撤权、缺少配置均保持 BLOCKED/NOT_RUN；
   不通过重复评分直到通过。重新验收保留新报告和原报告关联。
7. 评分记录绑定案例、问题/原文/规则/答案摘要、评测模型与端点、评分政策版本和实际调用。
   只在受权限保护的报告保存业务内容；公共验证报告不发布企业原文。

## 验收

本地合成用例必须覆盖错误答案带 VERIFIED、错误拒答、正确弃答、规则遗漏/重复、提示注入、
过期答案、跨组织/跨空间读取、前后撤权、模型失败和超时。正常 HTTP 任务→评分→报告链路
必须执行，不能只测提示文本。真实评分还须用独立审核样本校准；模型评分是质量证据之一，
不是客观真值或上线批准。未完成校准、全部必需用例、Worker 版本证明和既有硬门前，
阶段状态仍为 BLOCKED。
