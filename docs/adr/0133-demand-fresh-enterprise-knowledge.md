# ADR 0133：企业提问触发外部正文重新采集

状态：Accepted（P1 正文可信性前置增量；整体验收仍为 IN_PROGRESS）
日期：2026-09-14

## 定位与事实

蓝图第四部分的单一 Harness、Capability Gateway 和 Policy Engine 继续负责执行、
授权与审计。原有持续同步能保持索引更新，但不能证明当前问题开始后访问过外部来源。
用户明确要求每轮企业事实都主动查询来源，因此旧索引回答不能继续作为默认行为。

## 决策

企业知识默认 `live`。`knowledge.search` 及受管 `document.read` 等待现有持久同步
Worker 完成一次 **开始于当前 Run 创建之后** 的来源扫描，随后仅检索本次新采集、
完整且当前有权读取的正文。扫描开始时间由受信队列领取事务记录，重启/分页保留；
完成世代和实际开始时间与完成检查点一并提交。扫描结束晚于问题但开始早于问题不合格。
正文未变化也必须重新调用外部读取，文档版本无需因此递增。

等待器只提前当前主体的空闲来源轮询时间，不改权限、绑定、扫描游标或有效租约。
实际发现、分页、逐文读取仍由现有 Python Worker 经 Gateway/Policy 执行，调用保留审计。
不引入第二个 Agent 循环，不把凭据交给模型。最多16个来源、默认100秒有界等待；
不自动截掉来源以隐藏失败。等待中来源集合变化、未配置、离线、失败或超时均保留缺口。

当前问题取得的扫描证明可供同一 Run 后续多维检索和逐页阅读复用；新的 Run 再次查证。
结果和 Run 计划保存来源标识、世代、扫描时间、未完整取得的文档数量；不以索引查询时间
冒充外部调用时间。只有 READY、checked_at 不早于当前 Run、读取世代满足证明的资料
可以作为证据。既有版本/ACL/密级/发布屏障继续适用。完整扫描不代表每篇正文都完整，
失败、不支持和部分文档继续显式计入缺口，不能对其生成答案。

无法取得实时证据时不请求模型编造答案，返回具体补齐方向并停止无意义的模型补查。
用户显式选择的原生上传文档仍按独立阅读合同处理；它不能成为未选择企业问题的后备库。

## 兼容、迁移与运行

本 ADR 明确批准默认行为变更：没有可用外部来源的企业知识问题会说明无法查证。
仅测试/开发可显式设置 `indexed-development` 来运行已有合成索引夹具；预发/生产拒绝
该设置。HTTP 资料管理、索引浏览、显式资料选择和工单合同不变。

迁移 `c5d7e9f1a3b5` 在现有来源表新增三个可空字段和一致性约束。旧数据不补造扫描时间；
升级后须完整重扫才能回答。升级顺序为数据库、源码匹配的同步服务、API；能力描述符的
120秒超时需通过已有登记流程发布，旧固定版本不原地改写。回退前停用实时新代码并保留
审计备份，随后回退此迁移；历史 Run 中的证明不重写。未部署或未执行厂商 UAT 不计通过。

## 当前边界

本增量复用已接入的受管钉钉知识库遍历，不冒充供应商语义搜索。大型库可能超时，需要
后续受治理的目标发现与按需读取，不能为省时接受过期索引。云效、日志和 Skill 的每轮
实时读取仍按后续各自合同实现；云效保持只读，不执行其源码。P1 独立语义评分和 P2—P5、
正式 Phase99 门禁未完成。测试和真实数据库验证结果记入 P1 报告。
