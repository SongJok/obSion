# ADR 0132：可恢复的产品验收观察

状态：Accepted（P1 本地增量；全阶段仍为 IN_PROGRESS）
日期：2026-09-14

## 定位与问题

蓝图第四部分要求一个持久 Harness 和可审计的 Verify/Reflect 闭环。P1 已有正常任务
入口的验收驱动，但进程中断后不能续查已提交的任务；直接重跑可能重复创建，旧分数也
不能证明当前答案和权限仍然有效。优先修复现有闭环，不增加第二套执行器。

## 决策

`acceptance run --resume-from <旧证据目录> --output <新目录>` 仅续查已知任务，绝不
重新提交 Thread/Turn。创建前保存请求阶段，取得标识后原子检查点；响应丢失保持 BLOCKED，
从未开始的用例保持 NOT_RUN。未实现供应商/任务创建幂等对账时，不猜测未知 Run 标识。

续查校验原始输入、完整案例清单、候选、profile 和摘要，禁止同一 Run 充当多个案例。
经现有受权限保护的 API 核验 Workspace → Thread → Turn → Run 关系、问题、上下文、
模型/Agent、配置和资料，再读取实际发布答案并重新评分。旧 PASS/VERIFIED 和正文均不能
直接带入新成绩。无独立评分器仍为 NOT_RUN，P1/Phase99 门禁不变。

任务等待预算从首次提交时固定，重启不能重置；同时由服务端 Run 创建时间限制上界。
此前超时或意外等待用户的尝试保持 FAIL，迟到完成不能提升分数。需要取消时使用原有
授权接口；取消响应失败记 UNKNOWN，保留原始失败，不声称清理成功。

每次续查生成全新 0700/0600 证据目录，以原报告 SHA256 连接历史，不覆盖旧记录。
前置配置检查失败也保留已知任务标识与原始失败原因，后续恢复不会丢失定位或清除超时成绩。
原报告只是恢复定位信息，不是已签名的可信部署证明。

## 兼容与迁移

CLI 新增可选参数；无此参数时仍创建新验收任务。报告 schema_version 从 1 增为 2，
附加 admission_state/requested_at/deadline_at 和前报告摘要。历史 v1 报告继续保留可读，
因缺少可靠提交阶段和截止时间不支持自动续查；不补写或伪造这些历史字段。
不改数据库、任务 API、事件合同或外部连接器，无数据库迁移。

## 验证边界

专项包含真实应用 HTTP 入口的创建、发布和恢复，以及显式合成提供方的进程中断、来源
撤权、配置变化、输入替换、重复 Run、任务关系、超时和取消失败。模型质量和厂商 UAT
不由这些测试证明。完整验证结果见 [P1 报告](../phases/PHASE-P1-REPORT.md)。

每轮外部实时查询和独立语义评分仍未完成；新鲜度要求及 GitHub main 写入授权详见
[范围决策](../product/productization-scope-decisions.md)。
