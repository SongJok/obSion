# ADR 0083：钉钉 Stream 持久接收与控制面传输边界

日期：2026-09-06

状态：接受，限定于 M1 入站实现；不代表真实租户、完整机器人或生产验收通过。

## 背景

Stream 的厂商 ACK 必须以控制面持久接收为依据，不能等待模型运行，也不能以本地内存队列代替 Inbox。既有 SDK 内部请求接口不保留 HTTP 状态且接受任意 2xx，无法验证接收契约要求的精确 202。

## 决策

- 以可选依赖固定官方 `dingtalk-stream==0.24.3`；只使用连接管理、回调规范化和 ACK 接口，不使用 SDK 回复能力。普通 IM 客户端和 Inbox worker 不强制加载 Stream SDK。
- 安装 UUID、企业和应用来自受管启动配置；消息不得指定控制面 URL、组织或安装路由。仅转发稳定业务事件 ID、sender、conversation、会话类型和文本五字段，授权由控制面完成。
- `inbox.py` 允许精确的 httpx 架构例外，仅访问固定控制面安装域 Inbox 路径；禁止环境代理、重定向、URL 用户信息，非回环地址要求 HTTPS。不引入第二 Harness、数据库客户端或厂商发送通道。
- 只有精确 HTTP 202 与合法、匹配安装和事件的无正文回执才返回成功 ACK；接收超时或响应不确定时不伪造成功，由厂商重投与持久幂等恢复。
- Stream 不调用 process。独立 worker 遍历持久 RECEIVED 列表，并请求控制面创建唯一逻辑任务；按 UUID keyset 分页，失败事件也推进游标，尾页后重试，避免固定队首失败造成饥饿。事件不被客户端删除。
- 禁止入站命令同时配置出站或 local-outbox，避免把持久接收误报为最终回复。
- SDK 使用独立、不传播的禁用 logger，避免其默认日志输出 ticket 和消息正文；不得全局关闭其他应用日志。

## 生命周期与兼容性

官方 0.24.3 没有公开 stop API，且其连接循环会吞掉 asyncio 取消；Stream 作为独立受监督进程使用 SIGTERM 停止，不宣称已实现可靠优雅取消。未知接收结果依赖服务端持久幂等，而不是保存本地消息字典。

公开 SDK 接口核验、启动方式与限制见 [操作说明](../product/im-m1-stream-operations.md)。升级 SDK 必须重新验证 `CallbackHandler.raw_process` 的 ACK 行为。旧入口保留兼容，不作为本入口失败后的直调模型或 webhook 回复降级路径。

## 验证边界

架构测试限制 httpx 例外并禁止回调执行任务或发送；MockTransport 测试覆盖响应状态、回执、重定向、超时、重复事件、分页和恢复。官方 SDK 的离线回调兼容测试不等于真实租户连接。

真实 ACK 延迟、厂商重投行为、受管安装配置、群受众授权、Gateway 出站及最终回复均需独立验收。本 ADR 不授予外部发送权限，不满足 M1 全部门禁。
