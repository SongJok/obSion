# ADR 0131：P1 任务主题、正文预算与质量验收边界

状态：Accepted（本地增量；P1 全阶段仍为 IN_PROGRESS）
日期：2026-09-13

依据 [P1—P5 要求](../product/productization-p1-p5-requirements.md)，本轮从 P1 开始。
正式 Phase 01—98 和 Phase 99 发布门禁保持原义。用户另外要求云效代码不可修改，
本地代码必须与 GitHub main 无冲突；读取 GitHub/云效不意味着获准推送、合并或部署。

## 决策

1. 沿用单一 Python Harness。在路由前仅从最近一个、同主体的已捕获会话 Run
   恢复明确指代型追问的任务问题；先调用既有 KnowledgePublicationGuard，按当前组织
   查询前 Run。不同主体的历史仍按既有不可信上下文处理，不提升为当前用户指令。
   明确的新话题不继承旧主题。任务问题进入既有 RunIntent JSON、计划、检索、调查、
   作者和独立复核；当前 Turn 保留原始请求。连续追问保留有界原主题。
   同一已授权会话的结构化仓库/服务选择以 CONVERSATION 来源重新解析，仓库必须仍在
   当前主体的可见目录内；当前显式选择优先。撤权后不自动换用目录中剩余的仓库，进入
   有界澄清。除下文明确列出的用户任务槽位外，其他槽位不随选择继承；审批和执行授权不继承。
2. 规范/制度/指南的查询优先按知识处理；明确源码、补丁、路径和调用关系请求仍走工程。
   “为什么”本身不足以证明线上事故。普通聊天入口同样识别企业追问，避免前置路由降级。
3. 超预算 JSON 证据不再只摘取 id/source。按完整正文段、代码围栏和 Markdown 表格
   选择，保留证据 id、正文索引及原有定位字段。按当前问题做确定性词面排序，恢复原文
   次序，记录 incomplete/omitted_blocks。容不下的原子块不截断；极小预算只给有效的
   缺失标记或空内容。此算法不是模型摘要，也不证明正文完整或语义正确。
4. 保留 evaluate-datasets 既有 status/PASSED 的离线子集契约，新增明确 scope、
   acceptance_status、answer_quality_status、quality_eligible 和逐用例 results。
   未执行的 RUN_OUTPUT 全部登记 NOT_RUN，整体 acceptance_status=BLOCKED，
   answer_quality_status=NOT_RUN，quality_eligible=false。--require-complete 对缺项
   返回退出码 2，供完整验收调用；既有离线路由/SQL CI 不冒充答案质量门禁。
5. 新增 `acceptance freeze/run` 和只读 `admin/runtime-identity`，冻结已有配置与原文
   摘要后从正常任务入口获取最终产物，独立评分使用单独合同。缺少真实评分器时默认
   NOT_RUN。部署声明不等于签名或 Worker 执行证明；子集结果不能解除阶段阻断。
   具体输入、权限、报告与恢复边界见[操作说明](../operators/productization-acceptance.md)。
6. P1 试点档案必须从实际目录发现清单，新增 `codeup.tree.list` 只读能力，限定固定
   commit 的 DIRECT 目录读取。保留 LFS、子模块、符号链接和禁读文件的元数据，不执行
   代码、不取其内容；超过条数/响应预算显式失败或不完整，不能静默筛掉后声称完整。
   此能力继续经过既有 Gateway、Policy、凭据代理、仓库 ACL 及共享限流。读取全部
   子目录仍须逐次授权；当前目录完整不等于整个仓库完整。
   工作台支持根目录、逐级目录、文本读取与返回父目录，每次导航重新调用同一受治理
   查询入口。前端核对仓库、提交和直接父路径，切换请求立即清除旧结果并忽略迟到响应。

## 兼容与迁移

不新增表、列或事件类型，不需要数据库迁移；新增兼容的只读运行版本接口。复用已持久化且可审计的
RunIntent、RunConversationSnapshot、计划和上下文预算。历史 Run 不被重写。
离线输出只增字段，旧调用仍可运行；完整验收显式启用严格退出码。

## 验证及尚未完成的合同

开发回归包含 100 条中文路由/多轮组合、来源预算结构、极小预算 JSON 完整性、普通话题
切换，以及正常 HTTP 入口三轮知识任务的检索/作者/复核/发布一致性。模型为显式测试
适配器，既不是实际模型质量证据，也不是独立保留集。结果见
[P1 报告](../phases/PHASE-P1-REPORT.md)。

本增量没有证明所有自然语言追问、结构化资料选择和期望产物、所有来源并发撤权、运行版本
证明、完整阶段验收驱动、独立保留集评分或三仓库运行档案已经完成。P1 继续实施；
P2—P5 不提前计完成，真实环境缺失、14 天试运行及人工发布授权不能用本地测试代替。

## P 命名空间与真实资料补查

项目状态检查器显式验证注册的 P1 报告和配套架构门，两份均须 IN_PROGRESS，
与既有数字 Phase 及 Phase99 独立计数；未登记的 P 报告和没有完成账本的完成声明仍拒绝。
保持既有严格错误生产者审查；Runtime源码移动后仅更新3处已核对的转发位置行号。
新增目录参数拒绝分支登记一个既有 `codeup_operation_invalid` 生产者，并核对 REST
错误转发的新行号；未扩展任何错误码允许范围或减弱静态审查。

临时 PostgreSQL 验证暴露全局同步队列测试共享数据库产生的干扰。保持领取、恢复、
旧租约拒绝和缺失项标记的全部断言，改为每项使用真实迁移后的独立测试数据库；不在
生产调度器增加测试专属组织过滤，不截断或删除操作者指定的原数据库。

本地私有真实试点档案（`docs/product/p1-pilot-runtime-profiles.md`）和首批24条冻结保留用例已落盘，
完整tree、CI/镜像/测试入口和独立评分尚待实现/验证，详见P1报告。

2026-09-13 用户补充决策：允许为真实依赖 iOS/UIKit 的 DDBusiness 增加受控 macOS/Xcode
验证环境。其控制和授权仍通过同一 Python 控制面、Gateway/Policy，沿用命令账本、
来源固定、预算和干净实例独立验收；云效代码写入仍禁止。此处记录范围授权，不是已
部署/已隔离的声明。P3实现时另行记录具体隔离方案及真实验证证据。

同日后续用户明确云效代码只读、可以不运行云效代码；以该最新指令调整范围。
云效源码真实构建和受控 macOS 环境不再是当前交付前置条件；未执行项继续 NOT_RUN，
不能代替为通过。完整适用范围见[范围决策](../product/productization-scope-decisions.md)。

## 选定资料、输出要求及原生资料撤权增量

`context_refs` 增加严格的 `task_context` 合同：最多 4 份本地索引资料、AUTO/TABLE/BULLETS/REPORT
输出形式和最多 8 条有界约束。字段未提供表示可继承；显式空数组或 AUTO 表示清除或重置。
用户字段不能携带版本、来源凭据、执行授权或任意扩展字段。普通上传附件合同保持独立。

资料、输出形式、约束保存到既有 RunIntent.resolved_slots，继承时记录会话快照来源；当前
结构化字段优先于本轮自然语言形式要求，后者优先于历史。新话题不继承。每轮资料范围通过
Policy 和当前索引 ACL/版本检查后固定；实际正文读取仍通过 Gateway 的 document.read。
选定资料将本轮视作资料问答，初始计划不全库搜索；后续模型调查只能续读范围内的固定版本，
服务端拒绝越界搜索建议，不能仅靠提示约束。显式仓库选择解除旧资料范围；同一请求同时
选择非空资料和仓库被拒绝。解除资料范围恢复普通受权检索，不等于扩大任何权限。

KnowledgePublicationGuard 增加原生索引检查：由 Gateway 留下的组织内不可变 INTERNAL
能力版本识别本地知识来源，避免把外部提供方的 UUID 当成本地资料 ID。发布前、会话继承和
历史内容读取逐份重查当前主体、Policy、ACL、删除及版本；受管来源继续执行原有提供方检查。
检查保留逐资料 Policy 决策和审计，历史读取不把决策关联到被模型占用的 Run 行。
既有 PostgreSQL 来源屏障及 Document/DocumentVersion 触发器继续承担并发发布顺序，无新
数据库结构。若最近任务被撤权，追问不能回退到更早的可见任务；快照后撤权同样停止。

Web 普通提问框提供资料搜索选择、输出形式和补充要求，独立展示当前保留的任务要求。
失败保留草稿，成功、切换任务/空间清除本轮草稿；搜索取消和过期响应隔离。公开 intent
只附加上述用户任务字段，不公开其他内部解析槽位。当前接口兼容 CLI/IM 原 context_refs；
真实钉钉交互、独立模型遵循形式的质量比例和全部来源失效验收仍未完成。
