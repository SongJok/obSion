# ADR 0107：日常问答与企业证据问答分域

日期：2026-09-11。状态：已实施，验收进行中。范围：用户明确追加的日常问答，Phase 98 / M1 产品入口增量。

## 问题与基线

现有 Understanding 仅把完全匹配的问候词识别为 CONVERSATION；“你是谁”和“解释什么是机器学习”
均进入 KNOWLEDGE。真实模型基线确认，两者都因没有企业文档而返回资料不足。不能通过放松企业
证据门禁，或让模型把自身知识冒充企业资料来修复这个使用问题。

## 实施契约

- 保留 CONVERSATION 简单问候及既有企业路线。新增无外部操作的 GENERAL 路线，用于身份介绍、
  常识解释、文字起草/改写/翻译及示例代码等日常请求。请求分类与权限授权是两件事。
- 企业资料、当前项目、仓库、业务指标、生产资源及执行动作优先走原受治理路线；明确的资料引用
  不能被“日常问答”前缀取消。无法确定属于日常范围时，保留原路线，不猜测企业事实。
- GENERAL 继续使用同一 Workspace → Thread → Turn → Run → Step → Event 和 ModelGateway，
  受既有身份、预算、分类、取消、超时和审计约束。计划无 Capability 步骤、无工具调用、无外部写入。
- 日常回答可使用通用模型知识和用户当前提供的内容；不能声称读取了未调用的数据源、完成了工具操作、
  通过了代码测试或查证了实时信息。无实时来源时明确能力边界，不编造天气、价格和新闻。
- 日常对话上下文只使用已授权的相应对话；企业历史和记忆不能变成通用模型的事实证明。
  日常续问须保留原任务类别，不能把企业续问自动降为无证据回答。
- GENERAL 不产生企业事实 Claim、伪造 Evidence 或 VERIFIED 的企业核验记录。界面明确显示通用回答，
  不把“未进行企业证据核验”显示为一个虚构的置信度或资料不足错误。
- 知识问答的 Output contract v2、同 Run 引用校验和 WITHHOLD 屏障保持有效。GENERAL 不是工具权限
  或企业答案核验的逃生通道；回放与不同入口使用相同语义。

## 验证要求

覆盖中英文日常请求、身份、解释、写作/翻译、续问、无模型、模型错误、实时信息边界，以及企业
资料/代码/指标/生产访问反例。验证实际 Model Gateway 内容质量和点仔收发，保留完整回归及
PostgreSQL 运行证据；不得用接口返回 200 或存在回复代替内容验收。

## 实现与迁移

日常识别采用保守的中英文文本规则，已登记业务指标、显式企业来源、附件和操作请求优先保留原路线。
识别规则不是权限决策，仍经过原身份与 Policy 流程。IM 收件标识 `im_inbox` 和 `im_delivery`
只表示传输来源，不是企业内容引用；其他引用不能通过此路径绕过证据要求。不能确定的文本仍进入原路线。

GENERAL 只向 ModelGateway 提供固定平台策略、当前问题及同组织已授权的连续 GENERAL 对话后缀；
不传入企业记忆、注册连接器描述和工作空间说明。已有业务指标目录只用于保留受治理路由，不作为模型资料。
模型请求、答案产物与审计的分类至少达到工作空间分类，敏感空间通过既有私有模型路由执行或明确不可用。

GENERAL 计划没有 Capability 步骤，不产生企业 VerificationAssessment；VERIFY/REFLECT 步骤、事件、
答案与预算仍持久化。企业核验的数据库约束没有放宽。日常答案标记 `response_kind=GENERAL`、
`verification_scope=not_applicable`，verified=false；界面显示“通用回答”，不显示置信度。
格式门只核对结构与声明范围，不声称证明模型回答的语义正确性。真实内容质量另外逐题验收。

没有数据库迁移。保留 `intent.detected`、`plan.created`、`critic.completed` 的冻结 v1 字节与校验和；
新增明确的 v2 生产者和注册校验和，仅 GENERAL 使用 v2。其他路线仍产生 v1。v2 的日常意图没有虚构
查询时间范围，日常检查不能标记为企业核验通过。事件目录仍为 98 种事件，增加到 101 个版本。
消费者必须随契约包升级；回放复制固定答案与范围，不重新访问模型或连接器。

本增量不代表完整企业底座、自主项目执行或生产晋级完成。
