# ADR 0108：钉钉 Stream 建连超时与无凭据诊断

日期：2026-09-11。状态：已实施，真实消息验收中。范围：M1 真实入口稳定性。

真实测试 20、21 的发送任务 SUCCESS 不能证明机器人收到消息；对应 Inbox 尚未出现。检查所安装
官方 SDK 0.24.3 的 `open_connection()`，发现同步 HTTP POST 没有设置任何超时；SDK 日志又会输出
ticket、厂商原文，因此不能直接打开其调试日志。该缺陷可能造成长期等待，但尚不能断言它解释了全部丢失或延迟。

在同一入站适配器边界为官方建连请求提供有限连接/读取超时，保留固定服务地址、应用身份、订阅及 SDK
WebSocket 消息/ACK 流程；不修改全局 HTTP 客户端，也不放开凭据和原始消息日志。只记录本地定义的
开始、成功、超时或失败状态。该适配器只连接已有明确安装，不创建新授权或扩大订阅。

需验证超时后重连、失败日志无秘密、正确订阅、两个现有 Stream 入口、真实已授权 zziv 连接及收件。
不新增数据库模型，不把本地重启视为根因修复或正式生产验收。

实现位于既有 `obsion_im.dingtalk` 网络边界；未引入额外 HTTP 模块豁免。保留 SDK 日志完全禁用，
通过每个实例的 keepalive 包装记录已连接与生命周期结束，原协程和参数照常执行。拒绝任意 origin
环境覆盖是本增量明确的安全收紧，不影响当前受管官方 origin；不默许未知代理获得安装凭据。
