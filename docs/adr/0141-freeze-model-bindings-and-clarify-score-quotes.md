# ADR 0141：冻结模型绑定，明确评分引文协议

状态：Accepted（P1 产品化增量）
日期：2026-09-15

## 已复现的问题

模型目录原来只返回Profile配置和Endpoint目录，没有Profile到Endpoint的绑定及优先级。
正常管理API增加绑定后，冻结驱动仍看见相同配置摘要，错误地完成了另一个PASS子集。
回归用真实应用入口复现该问题，没有修改原有成功/失败断言。

另一项真实独立评分诊断命中`quote_not_substantive`：服务端要求每条通过规则的引文去除
外围空白后至少8字符（原文不足8字符时取其完整长度），提示仅写“substantive”，没有
写明数字要求。不能据此降低校验标准，也不能把这一次诊断归因于所有原失败样例。

## 决策

模型Profile管理读取响应兼容增加`bindings`，每项包含已有Endpoint标识与优先级，按
优先级和标识稳定排序。Profile与Endpoint同时按当前组织过滤；不返回供应商URL、凭据
引用或凭据值。原冻结配置摘要因此覆盖绑定变化，发现漂移后在创建候选任务前停止。

评分提示明确原有8字符下限、4000字符上限、短原文例外及逐字标点要求，要求完整的支持
语句。服务端规则不放宽，不增加模型调用或自动重试。提示变化产生新的政策SHA256；
新旧客户端/服务端政策不匹配时按既有合同BLOCKED，原批次仍保留原政策和成绩。

## 兼容、迁移与验证

无数据库结构迁移，既有顶层Profile字段保持不变。旧冻结Profile需明确重新冻结，不能
手工覆盖历史摘要伪装同一配置。该记录仍不是部署签名、Worker源码、Endpoint秘密配置
或完整密钥版本证明；相关阶段门禁继续保留。

冻结绑定回归修复前失败：绑定变化后仍PASS；修复后同一原断言确认`runtime_configuration_drift`，
必需案例保持NOT_RUN，未发送第二个候选Turn。评分、冻结/恢复、错误合同、模型网关和
安装包组合111项通过（62.90秒）。实模型对明确引文提示的验证单独记录，不以合成模型
结果宣称真实质量改善。
