# ADR 0139：独立评分提交与权限变更的数据库排序

状态：Accepted（P1 产品化增量）
日期：2026-09-15

## 问题

ADR0138 在模型调用后重新检查主体、Policy、来源与密级，但最后一次检查和评分审计提交
之间仍存在竞态。一次性 PostgreSQL 实测证明：另一事务可以在该窗口完成来源撤权，
评分事务仍准备返回此前的语义结果。同一事务中的权限变化测试不能证明这个顺序正确。

## 决策

模型调用结束后、最终授权读取前，调用既有 `acquire_source_publication_fence`，将最后
授权检查与评分审计提交放在同一短事务保护区。来源、用户、Policy、工作空间等权限变更
继续由既有数据库触发器取得互斥锁；评分采用共享锁。

- 撤权先完成：最终检查读取已提交变化，返回 BLOCKED 并清除语义证据。
- 评分先进入提交区：撤权在真实 PostgreSQL 锁上等待；评分提交后撤权才能完成。后续
  新评分必须被拒绝，不能使用先前的 PASS 证明当前仍有权限。
- 模型执行期间不取得发布锁，慢模型不能阻塞正常撤权；模型结果回来后再次检查。

该锁保护本地数据库权限的提交顺序，不保证外部厂商撤权已同步，也不让已发送给已授权
模型的内容可以被追溯收回。评分仍是有时间边界的历史质量证据，不是独立访问授权。

## 兼容与迁移

复用 `f2a4b6c8d0e1` 已有函数、触发器及错误合同，没有新表、新接口或结构迁移。
缺少必要迁移时按原函数失败关闭。SQLite 保留显式开发适配行为，不声称 PostgreSQL
并发保证。P1/Phase99 的业务质量、执行身份、签名和完整门禁不因此通过。

## 验证

正常 HTTP 任务和评分使用真实一次性 PostgreSQL，资料与模型明确为合成夹具。
四项用独立事务在模型期间完成文档 ACL、密级、用户或 Policy 变更，检查 BLOCKED、
真实模型调用账本、权限审计和候选 Run 不变。另一项用 `pg_blocking_pids` 检查真实锁等待，
不靠短睡眠推断顺序，并验证提交后的下一次评分拒绝。

修复前：4 通过、1 失败，失败明确复现最后检查后的撤权越过评分提交。
修复后：5 通过（13.33 秒），临时数据库升级和清理成功，没有连接生产数据库。
