# ADR 0114：开发环境受管钉钉正文读取

日期：2026-09-11。状态：接受（限定开发适配器）；同步与企业问答闭环未完成。

## 问题

Wiki v2 已能以真实应用身份发现组织目录，但原生 blocks 响应会漏掉引用块正文。
相同组织操作者的 DWS 完整 JSONML 可以取得这些文字。不可将有缺失的块响应当作全文，
也不可把人工读取或伪装的 HTTP 响应当成后台集成。

## 决策

增加显式 `dingtalk-managed-development` SDK 执行器，只支持
`knowledge.dingtalk.read`。它由受管宿主安装，默认 API 不启用它；现有 SDK echo、
MCP 和其他连接保持原合同，不增加第二个后端或任意命令能力。

调用经 Capability Gateway、L2 Policy、连接 grants、凭据代理和 Audit。
策略资源中的组织、知识库和节点必须与实际读取一致。适配器仅接受开发连接及封闭配置，
不接受 endpoint、任意 egress、命令、参数、环境变量、动态模块或可执行文件路径。
真实集成验收使用隔离 PostgreSQL 中登记的 Capability/Binding/Policy；不是模拟厂商响应。

应用密钥仍由 Gateway 的 CredentialBroker 解析；DWS 用户会话留在宿主凭据管理器。
宿主只允许固定的 `profile list` 和指定 profile 的 `doc +fetch --scope full --detail full`，
不使用 shell，不继承应用密钥或 DWS 覆盖环境。输出与运行时间均有界，取消会回收自建子进程，
stderr 不进入异常或模型上下文。宿主受信任的 DWS 二进制与认证端点管理不是生产沙箱证明。

每次读取前后检查 Wiki v2 同组织 TEAM 知识库、节点归属和原生权限完整分页。
仅识别相同组织、相同 userId 的明确 USER 读取角色：OWNER/MANAGER/EDITOR/DOWNLOADER。
READER 只有预览；未解析的继承、部门、组织、动态组和限时授权不产生本地读授权。
本地有效用户、安装与 sender 绑定也须前后成立，连接配置变化或撤销使结果不可接受。
既有安装绑定是操作者身份的信任根；同名用户、客户端当前组织和全局 profile 都不替代它。

完整文档封套必须包含匹配 nodeId、revision、成功状态与 `complete=true`。
解析仅消费正文节点与明确的 code 正文属性，保留段落、引用、简单表格边界；
未知标签、图片、卡片、合并/隐藏单元格、未还原的有序编号均留下明确缺口。
不将链接 token、样式、人员元信息或嵌入 metadata 展平为答案依据。

## 验证与迁移

同组织 10 篇真实文档均经新执行器、Gateway/Policy 和 PostgreSQL Audit 完成读取。
3 篇解析无缺口，7 篇仍有显式缺口；用户编辑后的正文版本也由真实返回取得。
详见正文读取账本与组织文档专项报告。SDK 旧行为、拒绝、取消回收和正文解析有专项回归。

本增量无业务 schema 变更。仅在隔离本地验收库登记开发连接、版本、策略与身份 fixture；
没有修改运行中 API 的连接、部署镜像或用户文档，没有调用模型，没有消息外发。

## 尚需交付

后台持久同步源/队列、自动增量、租约和失败恢复、正文入库、来源访问新鲜度与撤销的
检索屏障、AI 表格/附件读取和真实点仔文档问答仍未交付。不能仅凭读取前后校验便宣称
已经解决入库后的撤权；本地管理员权限也不能绕过未来的外部来源访问屏障。
