# ADR 0134：可完成且可诊断的完整覆盖率验证

状态：Accepted；本地及远端验证结果按 P1 报告记账。
日期：2026-09-15

蓝图要求验证和反思闭环。main 的完整覆盖率任务先后在25分钟和45分钟上限被取消，
对应运行34846309073、34851557547；其他已完成门禁通过，完整质量和容器门仍缺结果。
只延长时限没有获得通过证据，不能继续把这些取消记录视为成功。

保留唯一 Python 控制面及全部测试范围，开发依赖锁定 pytest-xdist/execnet。仅 CI 的
覆盖率命令显式启用四个本机隔离测试进程，按文件分配用例；同一文件始终在同一进程。
pytest-cov 合并所有进程的覆盖率，并按同一 pyproject.toml 中的70%门槛决定结果。
不设置分片低阈值，不手工筛选“足够通过”的用例。工作进程崩溃不自动重启；测试失败、
覆盖率不足、集合不一致和整个任务超时仍阻断原有容器/发布依赖。

保留既有独立的 wheel 契约测试，避免构建过程影响覆盖率环境；其余四个测试目录全部
参加同一覆盖率运行。增加逐项进度、最慢30项、120秒调用栈诊断和 JUnit 结果；XML
覆盖率和测试结果在任务结束时保存，任务中断时缺失报告不算通过。45分钟总时限保留。

无应用接口、数据库或权限迁移。已有开发环境通过锁文件同步增加测试依赖；普通本地
串行测试入口不变。回退只撤销 CI 并行参数及开发依赖，不能降低覆盖率或跳过失败。
真实并行完整回归和新 main CI 的结果才决定该运行方式是否可用；本 ADR 本身不证明速度
改善、真实厂商集成、独立语义评分或 P1/Phase99 完成。

方案依据：[pytest-xdist 文件分配](https://pytest-xdist.readthedocs.io/en/stable/distribution.html)
及 [pytest-cov 合并覆盖率](https://pytest-cov.readthedocs.io/en/latest/xdist.html)。
