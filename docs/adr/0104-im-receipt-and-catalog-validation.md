# ADR 0104：收紧 IM 回执恢复与云效目录完整性

日期：2026-09-10。状态：接受；属于 Phase 98 / M1 验证修复，不推进生产晋级。

## 问题

完整基线回归发现 IM 兼容 Bridge 可能对 FAILED 投递再次发送，且厂商发送成功后的控制面完成确认丢失没有进入明确的对账流程。云效目录适配器没有使用原生 API 的分页响应头，存在把单页误认为完整目录的风险。Stream SDK 默认日志和不稳定的运输消息 ID 也不适合作为持久入站边界。

## 决定

- 安装准入与每次入站重查同时接受协议、固定端点、出口、发送 grant 和凭据引用完整的 `dingtalk-robot` 连接器。原实现只接受 `dingtalk-docs`，与 Outbox 的机器人类型要求互斥；保留其他供应商及原文档连接器兼容行为，不开放通用 HTTP 类型。
- Bridge 仅允许 PENDING 兼容响应或带合法代次的 PROCESSING 响应进入发送；SENT 直接返回，其他状态要求对账。布尔值不能充当代次。
- 发送成功但完成确认失败时，带租约的 Bridge/Outbox 使用原 UNKNOWN 接口；无租约兼容路径使用现有失败接口的 UNKNOWN 语义。报告失败也不重发，持久租约负责后续恢复。保留原授权、受众、内容指纹和代次校验。
- Stream 优先使用厂商业务 msgId，以有界时间等待持久接收；不在 ACK 中返回原始异常，关闭 SDK 私有日志。unifiedAppId 可缺省，但显式提供时仍验证匹配，原 corp/app/robot 身份边界保持有效。
- 云效使用固定只读端点、明确排序、响应头分页总数与正文一致性校验、重复 ID 检查、有界组织目录，并拒绝压缩响应。不得把达到分页预算解释为已取全。凭据仍只经 CredentialBroker 解析，精确凭据反射从输出中移除。
- 本地回归入口显式排除 yunxiao_live，保留真实测试独立启用。

## 兼容与迁移

不增加数据库字段，不更改事件版本或公开请求结构，无需新迁移。现有 PostgreSQL IM Inbox 迁移往返与 schema drift 独立验证通过。配置缺项通过补充 `.env.example` 中已有默认项迁移，保留本地原有值；不提交本地密钥文件。

## 验证边界

详见 [本轮验证记录](../phases/productization-m1c-validation.md)。真实目录发现不等于所有仓库源码读取、机器人回答或 GA 验收；这些必须取得独立证据。
