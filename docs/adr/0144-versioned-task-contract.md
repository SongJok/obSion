# ADR 0144：在统一 Harness 内绑定版本化任务合同

状态：Accepted（H02 工程增量）
日期：2026-09-19

## 问题

现有 `RunIntent` 可固化路由、指标、维度、时间范围和已解析槽位，但没有一个同时
约束资料范围、对象、精确性、交付物、用户限制、权限主体、预算和完成判据的持久合同。
作者、调查、验证和输出因而可能使用不同的任务语义。追问只改时间窗或指标时，旧回答历史也可能
污染新 SQL、统计和 Claim。

如果把附件正文或检索文本当作合同输入，来源中的指令还可能扩大检索范围、删除用户筛选或
把权限快照误用为授权。这与“Policy 决定权限”、“来源是不可信数据”的边界冲突。

## 决策

### 兼容的 TaskContract v1

保留 `RunIntent.schema_version=1`，新增可选的严格 `task_contract` 子结构。历史 Run 可继续解析；
新 Run 在上下文探查后、计划前必须绑定合同。合同包含：

- schema 版本、修订号、父指纹和内容指纹；
- 目标、资料范围、业务对象、时间窗与时区；
- 精确性、交付物、用户与系统约束、允许环境；
- Principal/组织绑定与权限、角色摘要，只记录指纹；
- Step/超时/Token/成本预算、完成判据和必要信息义务；
- 变更字段及必须失效的旧产物类型。

指纹覆盖完整持久 payload。任何越过 Builder 的篡改都在解析时失败关闭。

### 资料范围与权限

资料范围显式区分精确附件、精确文档、精确仓库、经 Policy 过滤的企业资源和无外部资料。
精确附件/文档范围强制 `organization_search_allowed=false`；Planner 和后续调查都不能选择组织搜索。
合同不接收 Evidence 或附件正文，只使用 Turn 输入、当前授权的目录和重新验权的结构化上下文。

`TaskAuthority` 明确标记 `descriptive_only=true`。它不携带凭据、不向 Agent 暴露权限列表，也不能使
任何 Capability 变得可用。外部访问仍必须在执行时通过 Capability Gateway 和 Policy Engine。

### 信息义务与变更

单一进程内 `DimensionRequirementRegistry` 为知识、业务定位、统计、故障和代码任务生成硬义务/
可选义务，并允许领域插件在进程内注册扩展，不创建第二个 Agent 服务。H05 再实现义务状态机和
缺口驱动终止；H02 只建立可持久且可验证的义务合同。

追问先经现有授权目录解析。当前轮明确修改时间窗或指标时，只用当前轮重新解析该字段，
其他字段仍通过当前授权目录验证。变更会递增修订号，并使 Plan、SQL/Data Query、Statistics、
Evidence Review、Claim 和 Artifact 中受影响的部分失效。作者不再收到旧语义的对话或记忆文本。

### 统一摘要

只有一个去除原始 Principal/权限摘要的安全 `task_contract_summary`。Plan、作者提示、调查输入、
Verify Step 和 Answer Artifact 使用同一份内容；输出 Lineage 记录合同指纹。不保存或暴露原始隐藏思维链。

## 兼容、迁移与回滚

- 数据库迁移：无。合同保存在现有 `Run.intent` JSON 中。
- 历史无合同 Run 仍可读取和回放；新 Run 必须生成合同。
- 回滚代码不需要数据库降级，但旧运行时对含合同的新 Run 只能按其历史 JSON 展示，不得将合同降级为授权。
- SQLite 仅是本地/测试适配器；为使并发幂等 IM 收件在慢 CI 上等待真实写锁，连接锁等待由驱动默认 5 秒提升为 30 秒；生产 PostgreSQL 配置不变。

## 非目标

- 不引入第二后端语言、微服务或独立 Agent 循环。
- 不在 H02 实现 H03 资源关系图、H05 维度状态机或 H08 完整统计口径 DSL。
- 不把合同快照、Prompt 文本或 Agent 自述当作权限决策。
