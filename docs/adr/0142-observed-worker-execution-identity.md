# ADR 0142：记录实际 Harness 执行版本观察

状态：Accepted（P1 产品化增量）
日期：2026-09-15

## 问题

API 的 `runtime-identity` 只返回部署声明。即使 API 的提交和镜像声明与冻结 Profile
一致，另一台旧 Worker 仍可能执行或恢复任务。原验收没有读取执行者的独立记录，不能
识别这种混合版本。声明中填入 SHA 也不能证明包内容或签名真实。

## 决策

在唯一 Python Harness 的执行入口、计划或回放动作之前，追加
`run.execution_observed` v1 事件。每次进入执行或恢复都会生成新的 execution_id，记录
本 Runtime 实例标识、初始化时的提交/镜像声明，以及安装包的 Python/JSON 文件摘要
和数量。相同实例不会随着后续 Settings 修改而改写自己的初始化观察。终态 Run 不追加
这类观察。事件与原 Outbox、Run 序号在同一数据库事务提交，不另建任务后端或存储模型。

摘要以包内相对文件名与内容 SHA256 规范排序计算，包含事件与错误合同资源，不包含
环境文件、凭据、绝对路径或字节码缓存。拒绝符号链接、空包及超过明确上限的包；运行
环境缺少源码时记录空观察，不能伪造匹配。构建检查比较实际 wheel 与源码包的摘要。

`acceptance freeze` 在指定根目录存在控制面源码时，额外冻结 `worker_package_sha256`。
带此字段的验收逐页读取当前授权 Run 事件，检查每一次实际执行的包、提交、镜像及事件
身份；任一恢复执行不符、观察缺失、分页异常或伪称签名有效都在独立评分前 BLOCKED。
匹配只说明这项观察一致，不能直接给答案得分。旧 Profile 没有该字段时保留原序列化和
答案评分语义，其 Worker 证明阶段门禁继续未完成；不会给历史 Run 回填新观察。

## 证明边界

字段明确标记 `installed_package_at_runtime_initialization` 和 `signature_verified=false`。
这不是硬件远程证明、签名镜像验证、依赖完整性、内存中加载代码的测量，或对可变磁盘
的原子快照。生产仍需不可变安装、构建签名与可信部署验证，不能据此删除签名及 Worker
执行证明门禁。它能发现开发和运维的 API/Worker 混装，不能对抗已经控制 Worker 的攻击者。

## 兼容、迁移与验证

新增事件名而不修改冻结的既有事件 schema。事件目录由98类/102版本变为99类/103版本，
增加精确生产者与错误构造点登记；沿用已有 PostgreSQL Event/Outbox，不需要结构迁移。
事件读取继续采用原 Run/Workspace/来源授权，摘要中不添加企业原文或主机地址。

专项覆盖包重定位、源码/合同漂移、空包/符号链接/超限、初始化配置冻结、恢复追加与终态
保护、API声明相同而Worker不同、缺失/重复/跨Run事件、分页不前进、旧Profile兼容、
独立评分与签名门禁保留，以及真实wheel内容比对。测试 fixture 显式清空部署版本声明，
避免开发环境 `.env` 污染“未声明版本”的合成测试。最终验证数量见 P1 报告。
