# Obsion 0.80.0-alpha.1 — first repository-wide Alpha candidate

This is the first Alpha candidate that binds the entire implemented Obsion repository
to one verifiable release contract. It is an engineering candidate for maintainers and
operators—not a signed production release, external tag, or deployment approval.

> Frozen contract: the machine manifest's live-tree evidence binding (project status,
> phase reports, architecture reviews, Alembic ancestry, SBOM) was validated at the
> Alpha.1 candidate commit. Once the development line moved to `0.81.0-dev`, the
> manifest was frozen as a static historical record; this document keeps the full
> evidence narrative for reproduction at that commit.


## Product position

Obsion is an Enterprise Agent Runtime and Intelligence Workspace. Its durable center
is Workspace + Harness + Capability + Evidence + Policy, not a particular model,
connector protocol, chat surface, or vendor.

The release preserves these invariants:

- one Python control plane and one App Server;
- Workspace → Thread → Turn → Run → Step → Event as the durable Harness model;
- Observe → Understand → Plan → Execute → Verify → Reflect → Respond;
- all external execution through Capability Gateway and Policy Engine;
- factual output as Claims linked to Evidence, with independent Critic verification;
- credentials resolved only inside connector execution and never given to Agents;
- production data/code/log/metric/runtime access read-only by default;
- production writes, deploys, restarts, config mutation, generic HTTP delivery, and
  L4–L5 actions denied.

## Included implementation

### Foundation and trusted runtime — Phases 1–11

- identity, tenant isolation, RBAC/ABAC/resource policy, approvals, audit, redaction;
- one REST/WebSocket App Server with durable retry keys and resumable Event streams;
- Run state/cancellation, deterministic Replay, Model Gateway profiles, AgentSpec,
  persisted Harness Steps, versioned Capability Registry/Gateway;
- Evidence Fabric, atomic Claims, and Critic-ready inspection.

### Primary enterprise intelligence — Phases 12–24

- ACL-preserving Knowledge ingestion/retrieval and KnowledgeAgent citations;
- semantic catalog, SQL AST policy, read-only Query Gateway, DataAgent artifacts;
- read-only observability and engineering connectors, IncidentAgent Top1/Top3 fusion;
- independent verification graph, Code Graph, memory governance, and specialist Agent
  contracts without user-selectable backend Agents.

### Release and Experience clients — Phases 25–37

- evaluation gates, secret scanning, SBOM, Helm hardening, threat/DR/operator docs;
- CLI, IDE, IM, Desktop, Studio, and Eval as clients of the same App Server/Harness;
- stable IM principal mapping and governed delivery receipts.

### Capability transports and extensibility — Phases 38–54

- in-process MCP, SDK, gRPC, WORKFLOW, and AGENT transport adapters;
- deterministic workflow dispatch, Python Connector SDK, static plugin governance;
- Python/TypeScript/Java REST SDK surfaces;
- immutable Agent/Skill/Prompt versions, prompt pins/rendering, bounded conversation,
  Workspace, Evidence, and Tool-result context.

### Workspace projections and vendor integrations — Phases 55–79

- runtime SLO projection and Files/Reports/Dashboards/SQL/Evidence/Timeline rails;
- Feishu/DingTalk/WeCom inbound/outbound security plus Confluence Knowledge;
- shared vendor Knowledge budgets/provenance/citation UI;
- all vendor browse and ingest/sync routes through the no-Run Capability Gateway;
- durable principal-scoped no-Run write idempotency, terminal replay, conflict
  detection, and fail-closed UNKNOWN reconciliation.

## Compatibility and migrations

Public REST and `obsion.jsonrpc.v1` compatibility is preserved. Existing immutable
Capability, Agent, Skill, Prompt, Run, Event, Evidence, and Artifact pins remain
replayable. The candidate adds no Phase 80 database revision.

Fresh installs and upgrades use the 30-revision linear Alembic chain from
`241e275bde59` through `a79c4d2e8f10`. The machine manifest verifies one base, one
head, exact ancestry, continuous Phase reports/architecture reviews, and a matching
CycloneDX component version.

Schema downgrade is an incident procedure. Back up PostgreSQL and object storage,
validate the target version, and prefer restore into a new database plus tested image
rollback over mutating an active production database backwards.

## Verification

From a clean checkout with Python 3.12+, Node, JDK 21, PostgreSQL 17/pgvector, Redis,
and object storage available:

```bash
make bootstrap
make check
make test-java
uv run obsion validate-release-notes
uv run obsion sbom --output docs/release/sbom.cdx.json
```

PostgreSQL invariant and migration round-trip tests are explicit opt-ins and must use
an isolated test database. The non-writing Feishu browse is also explicit and consumes
operator-supplied process environment credentials without printing or persisting them.
The exact current-revision results are recorded in the Phase 80 report.

## Rollout

1. Reproduce `make check`, JDK 21 tests, Alembic drift, and SBOM from the same revision.
2. Back up PostgreSQL and object storage; test restore before changing traffic.
3. Deploy to clean staging with OIDC, external secrets, exact Origins, TLS, NetworkPolicy,
   read-only data identities, connector grants, rate/sync budgets, and OTLP configured.
4. Run Knowledge, Data, Engineering, Incident, replay/cancel, approval, and Workspace
   acceptance flows with authorized/denied tenant fixtures.
5. Enable vendor source browsing before ingest/sync, verify ACL/provenance, and retain
   UNKNOWN reconciliation procedures. Do not enable a write by editing a manifest.
6. Record UAT, data-owner, security, DR, and image/signature evidence before any
   production promotion.

## Rollback

1. Disable affected connector bindings, automation/action workers, and vendor delivery
   transports without deleting Runs, Events, Evidence, delivery receipts, or Audit.
2. Preserve operator idempotency ledgers and reconcile UNKNOWN outcomes before issuing
   new request UUIDs.
3. Restore the previous tested image/config/secret references and, when required, a
   verified database/object-store backup into a separate environment.
4. Re-run internal read-only smoke tests before restoring traffic.

## Known limits and publication status

- This repository has not created or pushed an Alpha tag, package, image, or external
  artifact. `externallyPublished` and `signedTag` are false.
- Staging, UAT, timed DR, live OIDC/secret manager, registry HIGH-CVE policy, and human
  security/data-owner sign-off remain operator-owned.
- Real permitted Feishu document ingest/citation and live message delivery require
  tenant-approved resources; DingTalk, WeCom, and Confluence live tenants remain
  operator-owned.
- Remote MCP servers, stdio spawn, third-party SDK loading, remote gRPC, external
  workflow engines, nested Harness Agents, and OS cgroup/container sandbox enforcement
  are not claimed.
- RUN_OUTPUT Golden Dataset observations must bind real terminal Runs; skipped fixtures
  are never presented as passing model evaluations.
