# Obsion 0.93.0-dev Alpha.1 native Anthropic and Gemini model adapters

Since Phase 6 every Model Gateway completion spoke the OpenAI
chat-completions wire contract; running Claude or Gemini meant fronting
the vendor with a proxy. Phase 93 adds native adapters for both
protocols behind the existing provider boundary — the Harness, the
redaction/budget/fingerprint/cost pipeline, and the endpoint schema are
untouched, and profiles route to `anthropic` or `gemini` endpoints
through exactly the same fail-closed path.

## What changed

- **AnthropicAdapter**: Messages API — system lifting, `input_schema`
  tools, tool_choice as auto/any/none/tool, text + tool_use block
  parsing, JSON-only instruction for json_mode.
- **GeminiAdapter**: generateContent — systemInstruction, user/model
  parts, functionDeclarations, AUTO/ANY/NONE/allowedFunctionNames
  calling modes, native `responseMimeType` json_mode, synthesized call
  ids for function calls.
- **Registry**: `SUPPORTED_PROVIDERS` now drives both the gateway
  adapter registry and admin endpoint/profile validation, so the API
  can never accept a provider the runtime cannot serve.
- **Fail-closed parsing**: malformed blocks, non-object arguments,
  negative token counts, and unknown part types raise
  `ProviderProtocolError` into the existing fallback path.

## Compatibility and migration

None. Endpoints opt in by setting `provider: anthropic` or
`provider: gemini`; all existing providers behave identically. Rollback
is reverting the phase commits.

## Known limitations

- Live Anthropic/Gemini verification with real credentials is
  operator-owned, matching the Feishu live-ladder precedent; this
  release ships the protocol implementation, not a vendor attestation.
- Anthropic json_mode is instruction-based (the API has no
  response-format switch); the gateway's JSON validation is the
  enforcement point.
- All six Alpha.1 candidate gates remain PENDING operator-owned items.
