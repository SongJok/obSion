# Obsion 0.75.0-dev vendor integration release notes

This engineering release consolidates Phases 68-74 and adds a CI-validated
operator contract in Phase 75. It is a development release, not a signed v1.0
production approval.

## Outcome

Feishu, DingTalk, and WeCom now share the same product boundary:

| Path | Feishu | DingTalk | WeCom |
| --- | --- | --- | --- |
| IM outbound | `feishu-http` to `https://open.feishu.cn` | `dingtalk-http` to `https://oapi.dingtalk.com` | `wecom-http` to `https://qyapi.weixin.qq.com` |
| IM inbound | signed/encrypted callback | channel-secured callback | Token signature plus EncodingAESKey decrypt |
| Public listener | TLS + Host allowlist + Encrypt Key | TLS + Host allowlist + app/webhook secret | TLS + Host allowlist + Token + EncodingAESKey |
| Knowledge connector | `obsion-feishu-docs` | `obsion-dingtalk-docs` | `obsion-wecom-docs` |
| Knowledge origin | `https://open.feishu.cn` | `https://api.dingtalk.com` | `https://qyapi.weixin.qq.com` |
| Knowledge operations | document ingest and wiki-space sync | document ingest and workspace sync | wedoc ingest and WeDrive-space sync |

IM is an Experience client of the single App Server. It never owns a model,
Planner, Policy engine, or Agent loop. Knowledge ingestion is a Capability Gateway
path and therefore still requires identity, `knowledge.write`, connector grants,
Policy, bounded rate/sync budgets, ACL, Evidence normalization, and Audit.

## Consolidated changes

- Phase 68 added explicit DingTalk and WeCom HTTP reply transports after
  control-plane `im.reply.deliver` authorization. Generic `--deliver http` remains
  rejected.
- Phase 69 added WeCom encrypted callback verification and AES decrypt. Ciphertext
  without a valid EncodingAESKey fails closed.
- Phase 70 added explicit public TLS ingress for DingTalk and WeCom with Host
  allowlisting and channel-specific security. Loopback remains the default.
- Phase 71 added DingTalk documents/workspaces to the existing ACL-aware Knowledge
  pipeline.
- Phase 72 added WeCom wedoc/WeDrive documents to the same pipeline.
- Phase 73 unified vendor Knowledge sync budgets, provenance, and REST/Gateway rate
  semantics. Silent truncation is an error.
- Phase 74 exposed source, connector, external id, revision, and operation in the
  Workbench without fabricating missing provenance.
- Phase 75 makes this release contract machine-verifiable and corrects stale
  operator guidance.

Earlier Feishu functionality from Phases 62-67 remains compatible: explicit HTTP
reply delivery, signed/encrypted callbacks, document/wiki ingestion, and public TLS
ingress use the same boundaries described here.

## Configuration contract

Secret values belong in an external secret manager or process environment. The
repository and connector manifests contain names or `credentialRef` values only.

| Concern | Required names |
| --- | --- |
| Feishu app | `OBSION_FEISHU_APP_ID`, `OBSION_FEISHU_APP_SECRET` |
| Feishu callback | `OBSION_FEISHU_ENCRYPT_KEY`; optional `OBSION_FEISHU_VERIFICATION_TOKEN` |
| DingTalk app | `OBSION_DINGTALK_APP_KEY`, `OBSION_DINGTALK_APP_SECRET` |
| WeCom app | `OBSION_WECOM_CORP_ID`, `OBSION_WECOM_CORP_SECRET`, `OBSION_WECOM_AGENT_ID` |
| WeCom callback | `OBSION_WECOM_TOKEN`, `OBSION_WECOM_ENCODING_AES_KEY` |
| Public listener | `OBSION_IM_TLS_CERT`, `OBSION_IM_TLS_KEY`, `OBSION_IM_PUBLIC_HOSTS` |
| Optional shared webhook signature | `OBSION_IM_WEBHOOK_SECRET` |

The public listener is a separately managed `obsion-im` process. The current Helm
chart deploys the control plane and Workbench; it does not create vendor apps,
register callbacks, or place vendor credentials in Helm values.

For each Knowledge connector, review `rate_limit_per_minute` and
`knowledge_sync_budget` (`max_pages`, `max_nodes`, `max_depth`) against tenant API
limits. An operator must provide an explicit ACL or authorize member-derived ACL
inheritance. Bot visibility and corp-internal flags never imply organization-wide
read access.

## Upgrade and rollout

Phases 68-75 add no Alembic revision. Still run the normal backup and drift checks;
“no migration” is an explicit release fact, not permission to skip verification.

1. Back up PostgreSQL and the artifact bucket. Run `alembic check` and the release
   validation commands below against the candidate revision.
2. Inject environment values through the deployment secret manager and allow only
   the origins in the matrix above. Do not add a generic outbound domain.
3. Deploy the control plane, Workbench, and separately managed `obsion-im` candidate
   from the same tested source revision.
4. Import or reconcile the three connector examples. Review grants, credential
   references, egress, rate limits, and sync budgets before activation.
5. Bind `(channel, sender_id)` to existing Users. Display names and nicknames have no
   authorization weight.
6. Validate loopback callbacks and local-outbox rendering first. In staging, validate
   vendor signature/challenge handling before enabling public traffic.
7. Ingest one permitted document with an explicit test ACL, search it as an allowed
   and a denied principal, and verify citation provenance in the Workbench.
8. Deliver one completed, Policy-authorized Run reply and verify the immutable
   delivery receipt. Never use a bot token as proof of user identity.

Release checks:

```bash
uv run obsion validate-release-notes
uv run obsion scan-secrets
uv run obsion validate-registry
uv run pytest --no-cov services/control-plane/tests/test_phase75_release_notes.py
make check
```

## Rollback

Disable the affected delivery transport and connector binding first. Preserve
delivery receipts, Events, Evidence/provenance, and Audit. Roll the control plane,
Workbench, and `obsion-im` images back together, restore the previous secret
references and egress policy, then re-run loopback IM and internal Knowledge checks.
No Alembic downgrade belongs to this release.

Do not delete vendor-sourced documents to simulate rollback. If upstream access was
revoked or an ACL mapping is suspect, disable the connector, retain the investigation
trail, and follow the data-exposure incident procedure.

## Known limits and release status

- Live tenant scopes, public DNS, TLS certificates, callback registration, and
  vendor-side quotas remain operator-owned.
- Automated and mocked HTTP tests do not prove a live tenant rollout.
- Unsupported node types are skipped explicitly; missing ACL fails closed; missing
  provenance stays “unrecorded”.
- Generic HTTP delivery, connector marketplace installation, a second backend
  language, production writes, restarts, and deploy actions remain outside this
  release.
- Staging deployment, timed backup/restore rehearsal, registry-side HIGH CVE policy,
  and human security/data-owner sign-off are still required before a signed v1.0.
