# Obsion 0.91.0-dev Alpha.1 web component-test stack

ADR 0067 deferred one decision explicitly: whether apps/web keeps its
Python-static-assertion-only verification or gains a real JavaScript
test stack. Phase 91 makes that decision on its own terms — the web app
now has an executable vitest + Testing Library suite covering the logic
Phases 88-90 introduced, wired into the same `npm test` fan-out that
`make test` and CI already run. Dev-only dependencies, exact-pinned,
nothing shipped.

## What changed

- **Stack**: vitest 4 + jsdom + @testing-library/react 16 (React
  19-compatible), exact-pinned devDependencies of `@obsion/web`;
  `vitest.config.mts` scopes discovery to `tests/**/*.test.{ts,tsx}`,
  maps the `@/` alias, and keeps globals off so test types match app
  code.
- **34 executable tests**:
  - `typed-evidence.test.ts` — every classifier envelope, the generic
    fallback, precedence rules, and each no-invention accessor.
  - `knowledge-citation.test.ts` — hits mapping, top-level fallback,
    and blank-field omission.
  - `api.test.ts` — error normalization (`request_timeout`,
    `request_cancelled`, `network_error`, `invalid_response`),
    control-plane error passthrough with correlation ids, and the
    `credentials: "include"` / `no-store` session transport invariants.
  - `evidence-content.test.tsx` — rendered output for every typed view
    (events, git diff, config diff, table with truncation note, code
    symbols, citations, raw JSON fallback) and the metadata ledger.
- **Wiring**: the workspace `test` script joins the root
  `npm test --workspaces --if-present` fan-out, so `make test` and the
  CI quality job run it with zero workflow changes.

## Compatibility and migration

None. Dev-only change; the production bundle and release artifact
manifest are unaffected. Rollback is reverting the phase commits.
