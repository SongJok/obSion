# Obsion 0.82.0-dev Alpha.1 artifact build and clean-room installation release notes

This engineering release follows the frozen `0.80.0-alpha.1` candidate contract and
proves that every Alpha.1 artifact class can be built from one revision and
installed or loaded in a clean environment. It is a development release, not a
signed production approval.

## Outcome

`make release-artifacts` builds, from the repository root of one revision:

| Artifact class | Output | Build path |
| --- | --- | --- |
| Python distributions | `obsion_sdk`, `obsion_cli`, `obsion_im`, `obsion_control_plane` wheels + sdists | `uv build` per package |
| TypeScript SDK | `@obsion/sdk` tarball | `npm run build` + `npm pack` |
| Java SDK | `obsion-sdk` JAR | `./mvnw package` inside pinned `eclipse-temurin:21-jdk` |
| Container images | `obsion-control-plane`, `obsion-web` | committed Dockerfiles, repository context |

`make validate-release-artifacts` then proves each artifact without the
development workspace: wheels install into a fresh temporary venv and every
package plus the `obsion`, `obsion-cli`, and `obsion-im` entry points smoke-run;
the Node tarball installs into a temporary npm prefix and imports; the JAR lists
its `dev/obsion` classes; the control-plane image import-checks `obsion` and the
Workbench image answers a bounded loopback HTTP probe. SHA-256 hashes, image
identifiers, the git revision, and every validation step are recorded in
`dist/release/<version>/artifact-manifest.json`.

## Boundaries

- All outputs stay in the gitignored `dist/release/<version>/` tree; nothing is
  pushed, tagged, signed, or uploaded to any package index or registry.
- The tool is standard-library Python with fixed argument lists, bounded
  timeouts, and no credential access; the Java build container is pinned and
  adds no runtime to the control plane.
- Package versions remain `0.1.0` during the development line; the release
  version is carried by the artifact manifest and image tags.
- CVE scanning of images and dependencies remains a CI (Trivy) responsibility;
  the local manifest records hashes, not vulnerability verdicts.

## Rollout and rollback

Run `make check`, then `make release-artifacts`, then
`make validate-release-artifacts`, and review the manifest before any future
promotion decision. To roll back, delete `dist/release/<version>/` and the local
`obsion-control-plane` / `obsion-web` image tags; no remote state exists. No
database change exists in this release.
