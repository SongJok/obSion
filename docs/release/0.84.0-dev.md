# Obsion 0.84.0-dev Alpha.1 live-tenant evidence ledger

This phase turns operator-run Feishu live validation into durable repository
evidence. A declared probe ladder runs against the real tenant under the existing
opt-ins, and the outcome is recorded as redacted, checksummed ledgers that the
Alpha.1 candidate gate validates offline. It does not change runtime behavior and
does not promote the release.

## Live evidence ladder

`docs/release/alpha1-live-evidence-contract.yaml` binds six probes to the existing
opt-in pytest nodes:

1. `feishu-tenant-token` — tenant authentication through `FeishuClient.health`.
2. `feishu-chat-listing` — read-only bot chat discovery; scope denial is a valid
   classified outcome.
3. `feishu-docs-missing-denial` — a nonexistent document must fail closed.
4. `feishu-wiki-space-list` — wiki space listing or correct scope denial.
5. `feishu-browse-gateway` — no-write source browse through the
   REST-to-Capability-Gateway path with Policy and Audit.
6. `feishu-send-probe` — optional single-message delivery through the production
   `feishu-http` channel; it still requires the operator's own
   `OBSION_FEISHU_SEND_LIVE=1` and an explicit `OBSION_FEISHU_LIVE_CHAT_ID`.

`obsion record-live-evidence --profile-label <profile>` (or
`make record-feishu-live-evidence` with `OBSION_LIVE_PROFILE`) runs the ladder and
writes `docs/release/evidence/alpha1/feishu-<profile>-live.yaml`. Each probe test
emits a structured record via `OBSION_LIVE_PROBE_DIR`; the recorder classifies
junit and record together. A post-opt-in skip, a missing record, or an outcome the
contract does not allow is `failed` — a skip is never a pass.

Ledgers carry classifications, bounded content-free details, timestamps, a
truncated SHA-256 app fingerprint, the recording revision, and a canonical
checksum. Credential-shaped values and forbidden keys are rejected at record time
and at validation time.

## Operator boundary

Phase 84 explicitly defers rather than simulates: clean staging and UAT, timed
restore drills, registry HIGH/CRITICAL CVE policy and signatures, live OIDC and
secret-manager infrastructure, human security/data-owner approval, and
maintainer-authorized publication. DingTalk, WeCom, public TLS ingress, and
permitted Feishu document content remain operator-owned; the ladder records
correct fail-closed denial instead of fabricating access.

## Architecture and migration

There is no runtime, API, Event, Capability, Policy, credential, or database
change. The recorder is release tooling and creates no Run, Turn, Event,
Evidence, Approval, or audit row.
