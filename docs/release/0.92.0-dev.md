# Obsion 0.92.0-dev Alpha.1 collaboration assignment and provenance

The collaboration backend has enforced assignment and source-Run
provenance since its phase — assignees must be active workspace
members, source Runs must belong to the same workspace, and clearing an
assignee is an explicit null. The Workbench surfaced none of it. Phase
92 closes that gap: members are selectable by name, source Runs are
attachable at creation, provenance renders on every record, and one
click jumps from a task or decision into the motivating Run's Runtime
inspector. One additive backend view change; everything else is Web.

## What changed

- **Member identity**: `WorkspaceMemberView` gains `display_name` and
  `email`, populated by joining organization-scoped User rows after the
  existing access check — no new endpoint, no permission change.
- **Assignment UX**: the task form gains a member selector (create and
  edit); edits send only changed fields with `expected_version`, and
  clearing the assignee is an explicit null the control plane
  distinguishes from "not sent".
- **Source-Run provenance**: task and decision creation offer a bounded
  (50), newest-first Run selector; task cards and decision details
  render the persisted link, falling back to `Run {id}` when the Run
  aged out of the option window.
- **Runtime link**: source-Run chips open the full inspection bundle in
  the Runtime inspector through the Workbench's existing
  `loadInspection` path.
- **Error mapping**: `workspace_task_assignee_invalid` and
  `workspace_source_run_mismatch` now surface actionable messages and
  refresh the selectors.
- **Route labels**: the Runtime inspector labels ANALYTICS, OPERATION,
  and SUPPORT routes in Chinese instead of showing raw enum names.

## Compatibility and migration

None. The view-schema change is additive; no migration, environment, or
configuration change is required. Rollback is reverting the phase
commits.

## Known limitations

- The source-Run selector lists runs from active threads only, newest
  50; older Runs remain valid provenance targets via the persisted id
  but are not offered as options.
- All six Alpha.1 candidate gates remain PENDING operator-owned items.
