# Obsion 0.88.0-dev Alpha.1 Workbench reliability hardening

The Alpha.1 candidate audit found that the Workbench and experience clients
were functionally complete but carried reliability gaps typical of a fast
build-out: unbounded requests, a single point of failure in the admin
console's 22-endpoint `Promise.all`, unhandled async results in the Eval
view, an invisible REST fallback when the realtime stream cannot connect,
and — most importantly for a governance product — canned declaration text
that could enter approval and audit records without a human actually
confirming anything. Phase 88 closes those gaps without expanding the frozen
Alpha.1 product surface.

## What changed

- **Bounded, normalized requests** (`apps/web/src/lib/api.ts`): every fetch
  is wrapped in an explicit `AbortSignal` timeout — 30s by default, 120s for
  document/vendor ingest and evaluation mutations — and failures normalize
  to `request_timeout`, `request_cancelled`, `network_error`, or
  `invalid_response` instead of leaking raw `TypeError`s or JSON parse
  exceptions. The HttpOnly cookie session contract is unchanged.
- **Route-level boundaries**: `app/error.tsx` (client boundary using this
  Next.js version's `retry` prop), `app/not-found.tsx`, and
  `app/loading.tsx` give the single-page Workbench a styled failure surface
  instead of a blank client crash.
- **Per-domain admin degradation**: the governance console loads its 22
  domains through `Promise.allSettled`; failed domains are named in a
  warning banner with a retry action while healthy domains keep rendering.
  Only a total outage raises the page-level error.
- **Async correctness in Eval/Data/Code views**: Eval results are
  generation-guarded so a slow response can never overwrite a newer
  selection, and every event-handler promise is caught; the Data and Code
  views distinguish loading, empty, and no-match states instead of showing
  "empty" while the catalog is still in flight.
- **Visible stream fallback**: the Runtime inspector shows a
  live / polling / interrupted chip for active Runs, so users can tell
  whether events arrive over the App Server stream or the REST cursor
  reconciliation path, and whether synchronization is currently degraded
  while the Run continues in the background.
- **No cross-Run attribution**: the inspector resets its evidence/artifact
  detail selection when the inspected Run changes, and the detail footer
  names the owning Run.
- **Operator-entered governance declarations**: the governed-action
  preflight no longer submits a hardcoded "已核对…" string — the operator
  must type their own verification statement (minimum length enforced),
  which is what lands in the approval and audit record. The Desktop shell
  guards every action with uniform error handling and requires a non-empty
  approval reason; the IDE extension treats a dismissed reason prompt as a
  cancelled decision and rejects blank reasons instead of substituting
  "Approved from IDE".
- **Single-flight uploads**: Knowledge document upload is guarded against
  concurrent submissions and the file input re-arms after completion.

## Boundaries

Client code only. No API, schema, capability, policy, or runtime change; the
candidate contract, recorded evidence ledgers, and all six PENDING operator
gates are untouched, and nothing here feeds promotion eligibility.
