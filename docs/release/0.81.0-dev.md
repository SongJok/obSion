# Obsion 0.81.0-dev Feishu live reply validation release notes

This engineering release follows the frozen `0.80.0-alpha.1` candidate contract and
adds operator-run, opt-in live validation for the real Feishu delivery leg. It is a
development release, not a signed production approval.

## Outcome

The IM Experience path now has a complete operator validation ladder against a live
Feishu tenant:

| Step | Command | Vendor effect |
| --- | --- | --- |
| Non-sending probes | `make validate-feishu-live` | tenant token, chat listing, denied/missing document and wiki probes |
| Non-writing Gateway browse | `make validate-feishu-browse-live` | read-only Capability Gateway source browse |
| Single marked delivery | `make validate-feishu-send-live` | exactly one probe message to an explicit operator chat |

The send probe requires `OBSION_FEISHU_SEND_LIVE=1`, environment credentials, and an
explicit `OBSION_FEISHU_LIVE_CHAT_ID`. It runs the production
`FeishuHttpChannel.reply` contract—vendor namespace check, `feishu-http` pinning,
non-empty text, idempotency key, bounded retries, redacted errors—and asserts the
vendor message id. It never auto-discovers a target, never sends without the
explicit chat id, and never counts a skip as a pass.

`FeishuClient.list_chats` gives operators read-only, single-page-bounded discovery
of chats the bot belongs to so a send target can be chosen explicitly.

## Consolidated changes

- Phase 75 consolidated the DingTalk/WeCom vendor integration contracts.
- Phase 76 added explicit non-sending Feishu live validation and correct Feishu
  HTTP 400 business-error classification.
- Phase 77 unified vendor REST ingest/sync writes on the no-Run Capability Gateway.
- Phase 78 unified vendor source browsing on versioned read Capabilities.
- Phase 79 added principal-scoped Operator Capability idempotency.
- Phase 80 froze the repository-wide Alpha.1 candidate contract.
- Phase 81 adds bounded live Feishu chat discovery and the opt-in single-message
  send probe described above.

## Boundaries

- Live validation stays outside default CI; credentials are process-environment
  inputs only and are redacted from every error and assertion.
- The send probe is transport validation, not a Harness Run: it creates no Run,
  Turn, Event, Evidence, Approval, or audit row.
- Production replies still require a Policy-authorized delivery receipt; the probe
  does not weaken that path.
- DingTalk and WeCom live delivery validation remains unimplemented and
  operator-owned; generic HTTP delivery and all production writes stay denied.

## Rollout and rollback

Follow the ladder in the outcome table from top to bottom, choosing an
operator-owned test chat from the read-only listing. To roll back, unset
`OBSION_FEISHU_SEND_LIVE` and `OBSION_FEISHU_LIVE_CHAT_ID`; the probe then performs
no vendor call. No database change exists in this release.
