# Obsion 0.98.0-dev — Alpha.1 local operator access

Phase 98 adds a production-shaped bootstrap credential exchange for local and initial
operator access without creating a second identity, authorization, or Harness path.
An administrator can be enrolled through the local CLI, sign in through the
Workbench, and receive the same revocable HttpOnly session used by bearer exchange.

## What changed

- one organization-scoped password credential per User, stored as a salted,
  self-describing scrypt derivation;
- bounded cost, memory, block-size, parallelism, plaintext, salt, and derived-key
  handling, constant-time comparison, lockout, and opportunistic parameter upgrades;
- equivalent KDF work for unknown, ambiguous, and unenrolled identities to prevent a
  timing-based account oracle;
- CLI-only idempotent User/role/password provisioning with no password argument and a
  development/test-only weak-password escape hatch;
- a browser password-session endpoint and accessible password/token Workbench tabs;
- an additive Alembic migration plus an isolated PostgreSQL
  upgrade/downgrade/re-upgrade CI entry;
- complete `.env.example` coverage and local `.env` key parity, with optional
  API-only Compose injection for Gateway credential references;
- local Model Gateway validation through a complete, persisted Harness Run and a
  non-sending live Feishu validation pass.

## Compatibility and migration

Revision `d7f31a9c4b28` adds `user_credentials` without rewriting existing users,
roles, sessions, Runs, Events, or connector state. Existing development bearer and
OIDC exchange remain compatible. Disable password exchange before rollback and retain
another administrator path; downgrading deletes local credential derivations and
lockout metadata.

## Security boundary

Plaintext never enters PostgreSQL, Events, Evidence, Audit, Model Gateway, or browser
storage. Agents still receive Capability IDs rather than credentials. The locally
validated non-private endpoint serves approved PUBLIC/INTERNAL logical profiles only;
the `private` profile remains unbound and sensitive routing fails closed.
