# Obsion 0.90.0-dev Alpha.1 per-stage investigation narrative

goal.txt's incident-investigation chain (trace.search → git.diff →
config.diff → Evidence Fusion → Critic Verification) is only legible if
the Runtime panel shows *which step produced which evidence and which
conclusion that evidence supports*. The control plane has persisted all
three links since the early phases — `RunStep.started_at/completed_at`,
`Evidence.step_id`, and `Claim.evidence_ids` — but the timeline rendered
steps as a flat list with no correlation. Phase 90 turns the timeline
into a per-stage investigation narrative using only those persisted
keys: no new API, no inferred links, no synthesized text.

## What changed

- **Step duration from persisted timestamps**: each step shows its
  `completed_at − started_at` duration when both exist; missing
  timestamps render nothing rather than a fabricated estimate.
- **Step evidence chips**: every step lists the Evidence rows carrying
  its `step_id` as typed chips (bounded at six with an explicit overflow
  count); clicking a chip opens the Phase 89 typed Evidence detail in
  the Evidence tab.
- **Claim badges**: claims whose `evidence_ids` intersect a step's
  evidence render as `结论 C{n}` badges that jump to the Claims tab,
  completing the step → evidence → conclusion chain.
- **Unattributed evidence stays visible**: rows without a `step_id`
  (for example document attachments ingested at Run start) appear in an
  explicit "未关联步骤的证据" section instead of disappearing.

## Compatibility and migration

None. Rendering-only change inside `runtime-inspector.tsx` plus CSS;
rollback is reverting the phase commits.
