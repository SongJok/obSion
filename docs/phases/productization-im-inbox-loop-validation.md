# IM Inbox 并发测试的事件循环验证

日期：2026-09-15；范围：测试基础设施与CI诊断，不是生产功能或阶段验收。

GitHub运行34948510341（8b7a84c）的质量任务报告
`test_hundred_concurrent_duplicate_receipts_and_processing`失败。公开检查注释仅有测试名，
日志下载返回403，未取得远端原始异常；不能把下列缺陷直接宣称为远端失败的唯一原因。

原测试在本地单独执行通过（8.77秒），在无网络、仅跟踪源码、0.5CPU的Linux容器也通过
（24.71秒）。检查发现8处数据库辅助读写用`asyncio.run`，跨到了另一个事件循环，却
继续使用由TestClient应用循环创建的AsyncEngine连接池。

通过独立诊断夹具先在应用循环耗尽真实连接池、让额外读取进入等待，再执行原计数函数，
原100次重复接收测试明确失败为`Queue is bound to a different event loop`（2.42秒）。
诊断释放连接的任务始终在原应用循环运行，清理后不保留连接或任务。

所有8处辅助读写改用`client.portal.call`。原100次接收、20次处理、唯一Inbox/Turn/Run
及权限、回滚、恢复断言全部保留；不改生产代码，不增加SQLite超时，不降低并发量。
