# 受控多轮查阅与真实密级验证

日期：2026-09-12。依据 [ADR0128](../adr/0128-governed-knowledge-investigation.md)。
当前为 Phase 98 开发增量，完整 M1/M2/M3、自主项目和任意 MCP 工具循环均未完成。

本次实现资料不足后的自主搜索/分页读取、继续生成及独立事实复核。模型只能提出受限的
只读动作，本地校验后经正式 Gateway/Policy 执行；新动作、轮数、预算和复核结果持久化。
受管钉钉正文版本、来源权限变化会阻止继续发布；相同候选不能通过重复读取同一正文换取再次放行。
日常纯文本问题保留独立路由。

实际检验发现并修复：明确引用手册的问题被“是什么”误分入 GENERAL；模型端点不接收资料
密级时却将原始检索摘要当成已验证答案；知识连接器没有把真实密级传给 Evidence/模型；
多轮规划遗漏工作空间等上下文的较高密级。上述问题均保留回归覆盖，不通过放宽验收解决。

实现过程与最终结果：

- 专项最终组合 58 项通过（36.44 秒），含受限工作空间/内部资料的跨轮次密级检查。
- 六项真实 PostgreSQL 场景通过：逐页读取、搜索后读取、持久恢复、规划期间失权、重复候选、轮数上限。升级至既有迁移 head 与无差异检查通过，临时测试库删除。
- 最终整合 Python 回归2650通过、262跳过、7排除（751.92秒）；此前中断的全量不计通过。
- 真实 K3 在明确标注的虚构开发资料上完成初次弃答→自主 READ→重新作答→完整复核；4次真实调用、82.36秒。初始7个检索片段没有目标句，最终证据来自新增读取页。
- 真实企业来源仍维持 RESTRICTED；模型范围变更前保持 PUBLIC/INTERNAL，真实资料未降级。用户随后明确允许两个端点处理机密及受限资料，隔离环境已通过受控管理API更新。
- 日常环境旧版存在密级传递缺口，发现后先暂停来源；最终修复版已部署并恢复6篇可用，原文档标识保留。纯文本问答继续运行。

首轮真实问题误走 GENERAL，第二轮虽走 KNOWLEDGE 却在零模型调用下发布检索摘要，均不计
通过。第三轮因隔离库旧描述符保留 RESTRICTED 下限而正确返回模型不可用；此轮没有模型
调用。显式 INTERNAL 下限的新版本保留旧描述符，之后再验证真实模型；不修改历史描述符。
测试资料密级/正文变化仅涉及本轮创建的虚构资料，真实企业文档未被降级。

新增密级管理API只修改classifications，保留地址、模型和凭据；要求models.write且Policy为ALLOW。
权限不足、跨组织、DENY/ASK/MASK和非法配置均拒绝。10项API测试通过（11.82秒），包含
其他配置字段原样保留（更新时间正常更新）及成功/拒绝审计。用户许可落实为指定操作者、两个端点ID、
指定操作的窄范围Policy，隔离及日常两个端点均已增加CONFIDENTIAL/RESTRICTED。
企业资料真实问答和最终整合回归结果见下文。

端点密级更新后首次企业问题仍被已有“敏感资料必须走私有模型”配置拒绝，零模型调用、
未核验弃答，未计通过。用户已明确授权当前两个外部端点处理这些资料，因此仅调整本地
`MODEL_FORCE_PRIVATE_FOR_SENSITIVE=false`，仓库默认仍true；没有把外部端点谎称为私有模型，
模型ID/主机白名单及各端点密级仍强制执行。再次真实企业验证结果见下文。
