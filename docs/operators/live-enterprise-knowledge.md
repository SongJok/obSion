## 运行前提

主体映射、固定连接版本、读取授权和同步服务均可用；不通过提示词或默认角色补授权。
受管 DWS 仍是显式开发适配器，登录信息仅由宿主管理，不能复制到模型或公开仓库。

按数据库迁移 → 源码匹配的同步服务 → API 的顺序升级。迁移头 `c5d7e9f1a3b5`

`OBSION_ENTERPRISE_KNOWLEDGE_MODE=live` 是默认值。
`OBSION_KNOWLEDGE_LIVE_WAIT_SECONDS=100` 控制单次来源等待，上限110秒；完整任务继续
受原有总预算限制。开发或测试的合成索引夹具可显式选择 `indexed-development`，预发/生产

## 核对一次提问

从正常任务入口提交问题，查看该 Run 的 `plan.knowledge_live` 和知识证据 `freshness`：

- `requested_at` 是当前 Run 的开始边界；来源 `scan_started_at` 不得早于它。
- `scan_completed_at`、`generation` 标识实际完成的源扫描；正文读取也必须发生在边界后。
- `incomplete_documents` 是尚未完整取得的非目录文档数量，不能把扫描结束说成所有文档可答。
- `BLOCKED` 保留固定原因。此时答案应提示补齐来源/授权或重试，不能复述旧索引中的事实。

来源标识、时间范围可用于定位既有同步审计和上游读取 Policy 决策。证明只在同一个 Run
的后续查询中复用；再次提问时必须满足新的时间边界。当前没有可移植签名证明，不得把
该状态当作独立语义评分、供应商可用性认证或发布批准。

## 常见阻塞

| 原因 | 检查方向 |
| --- | --- |
| `source_not_configured` | 当前主体是否具有启用且完整登记的来源；不是其他管理员自己的来源 |
| `source_access_unavailable` | 当前身份和知识读取权限是否仍有效 |
| `source_scope_changed` | 等待期间来源集合发生变化，确认范围后重新提问 |
| `source_scope_exceeds_budget` | 当前实现最多16个来源，需要受治理的目标发现，不应隐藏失败来源以绕过限制 |
| `source_refresh_failed` | 检查现有同步审计、上游授权及逐文失败原因；不得自动切换身份 |
| `source_content_unavailable` | 扫描已结束，但有不完整文档且没有本轮可用正文；检查原绑定账号登录、正文权限与格式支持，不能用旧 READY 记录抵消故障 |
| `source_refresh_timeout` | 检查同步服务是否在线、旧扫描是否尚未结束、上游延迟与库规模 |

单次超时不会抢占同步服务有效租约；后续同步可继续按原游标完成。旧扫描在提问前开始时，
还需要新一轮扫描，不能改写旧时间使其通过。大型库的有界目标发现尚待后续实现。
用户可以明确选择原生上传资料进行阅读，该入口保留来源类型，不声称访问了钉钉。

## 验证与回退

必要反向用例：旧索引有答案但来源离线；正文不变仍再读；两轮间正文变化/撤权；旧扫描
晚完成；迁移中断后继续；来源集合变化；部分文档不被视为完整；Run 等待与同步事务并发。
并发合同必须使用一次性 PostgreSQL，SQLite 的单写入机制不能代表此项验收。

`b4c6d8e0f2a4`。来源和文档保留，新增扫描证明列移除；重新升级后必须重新采集。
